Overview

A text-summarization agent built on Google's Agent Development Kit, with an evaluation loop, an Obsidian second brain, and optional read-only Gmail access.

  • Python 3.11+
  • Google ADK
  • ROUGE-1 self-scoring
  • Obsidian
Get started Browse the source

What it does

Every turn is summarised into your vault as a linked note, and the note graph is browsable in Obsidian. Ask the same thing twice and the second time is answered from the vault with no model call at all — measured at 23.5 s for the first ask and 0.04 s for the repeat.

Why it is built this way

The part most people find interesting is the evaluation loop: edit the agent's instructions in agent.py, run ADK evals, and watch response_match_score move. That is the actual point of the repo — everything else exists to make the loop measurable.

Quick start

Docker and the Git CLI are the only prerequisites.

  1. Get a model key

    ./run.sh creates .env from .env.example on first run. Put your key in it — this is the only thing you actually need.

    GEMINI_API_KEY required
    The model backend. Get a free key from Google AI Studio.
    OPENROUTER_API_KEY optional
    Free models as a fallback when Gemini rate-limits you. Create a key on OpenRouter.
    MODEL_PROVIDER optional
    Set to openrouter to use the key above; defaults to gemini. See Models.

  2. Run it

    This picks your vault, builds both containers, and starts them.

    ./run.sh

    If you already have Obsidian vaults, it finds them — including the ones in your Obsidian config — and asks which to use. With nothing configured it auto-creates agent-vault in a local vaults/ folder.

    OBSIDIAN_VAULT_PARENT_HOST optional
    Host directory whose children are your vaults. Defaults to ./vaults. Usually written for you.
    OBSIDIAN_VAULT_NAME optional
    Required only when that directory holds more than one vault — it is never guessed. ./run.sh prompts and saves it.

  3. Open the agent and try a prompt

    The web UI runs on your own machine at http://localhost:8001 — open that after ./run.sh is up.

    Paste any text and ask for a summary:

    Summarize: Dogs are domesticated mammals known for their loyalty and
companionship. They are often called man's best friend. Dogs come in many
breeds, varying in size, color, and temperament.

    Every answer is written into your vault as a linked note, with topic notes and an index graph around it. Ask the same question again and the answer comes straight from the vault, with no model call.

    If you configured Gmail in step 4, the agent can read your inbox too:

    What are my latest 5 emails? Summarize them.
    Summarize all my e-mails related to Newsletters/Dzone label to this week.
    What did my manager ask me to do this week? Summarize the thread.

    You can also ask what you already know, which reads the vault rather than new text:

    What do I already know about deployment pipelines? Cite the notes.

    More examples, including the ones that do not work and why, are in Testing in the web UI.

  4. Optional: switch on the extras

    Each of these loads on its own; none of them affect the steps above.

    GOOGLE_CLIENT_ID
    GOOGLE_CLIENT_SECRET
    GOOGLE_REFRESH_TOKEN
    Read-only Gmail access. Create an OAuth client and enable the Gmail API in the Google Cloud console (also the Gmail API), then run text_summarizer/gmail_oauth.py once to mint the refresh token. Full walkthrough in Integrations.
    LANGFUSE_PUBLIC_KEY
    LANGFUSE_SECRET_KEY
    LANGFUSE_BASE_URL
    A trace per turn: latency, cache hit/miss, quality scores. Create a project on Langfuse Cloud, or self-host.
    CACHE_ENABLED optional
    Leave true for normal use. Set it to false when running adk eval, or the agent replays cached notes and the loop measures nothing.
Already use Obsidian? ./run.sh finds the vaults you already have — including the ones in your Obsidian config — and asks which one to use. One vault needs no configuration; several are never guessed between.

The vault

Summaries, chat logs, topic stubs, and an index graph land in a real Obsidian vault, so the notes form a graph you can browse.

Choosing a vault

obsidian-mcp serves exactly one vault, so with several on disk the choice is explicit and is never guessed — the agent and the MCP server refuse and list the candidate names. ./run.sh turns that into a numbered menu and remembers your answer.

The cache

Every note records a fingerprint of the request, and a repeat of that request is answered from the vault with no model call. Both sides compute the key in code from the same field, because a model-supplied key is paraphrased per run and would never match.

Provenance

Each note records the model that served the turn and the vault it landed in, read from the live invocation rather than passed in by the model. Unresolvable provenance is omitted rather than guessed.

Troubleshooting

The failures you are most likely to hit, and what they mean.

Gemini API key not valid

GEMINI_API_KEY is unset or wrong in .env.

'/vaults' holds N vaults; refusing to guess

Several vaults in the mount with no OBSIDIAN_VAULT_NAME set. Re-run ./run.sh and pick one — it writes the answer to .env.

'x' is not a directory under '/vaults'

A typo in OBSIDIAN_VAULT_NAME. The error lists the valid names.

obsidian-mcp keeps restarting

The MCP server exits rather than serve a vault nobody chose. Read its error — it names the candidates.

No Gmail tools in the UI

All three GOOGLE_* vars must be set, and the token valid.

Eval scores look great but nothing is being tested

Run evals with CACHE_ENABLED=false. Otherwise the agent replays a cached note and the loop measures nothing.
